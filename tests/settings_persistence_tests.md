Run `./tests/run_settings_persistence_tests.sh` on a Mac with Xcode and an installed iOS Simulator runtime. The runner generates the production Core Data model, builds a small isolated app, and creates and deletes a dedicated simulator. It never launches the user’s app or contacts a host.

The actual SQLite/Core Data tests cover fresh Native defaults, required identity initialization, one-time migration of global/PC/app quality, injected save failures and retry, explicit fixed/native/custom resolution policy, legacy bitrate preservation, and no-op reads. Output tests verify validation, store-before-notification ordering, unchanged values, rollback, independent child-context drafts, and coordinator enablement. Native uses the complete phone panel despite safe areas or simulated glasses. Host 3D compatibility and Raw packed dimensions use production configuration code. A background Native read plus an external timeout guards main/store deadlocks.

This replaces the former Stream setup fixture. Only the unreachable setup screen’s layout, screenshots, obsolete Full/Half controls, and preview labels were removed; database, migration, output, Native, and effective-resolution coverage remains. Live external rendering and calibration behavior have their own `run_external_display_tests.sh` fixture. Current picture/PC forms use `run_stream_controls_tests.sh`.

Live console and build diagnostics remain under `Build/settings-persistence-tests/<run>/`. No generated app, model, database, or simulator artifact is tracked. Optional environment variables `SETTINGS_PERSISTENCE_TEST_RUNTIME` and `SETTINGS_PERSISTENCE_TEST_DEVICE_TYPE` select another installed runtime or device.
